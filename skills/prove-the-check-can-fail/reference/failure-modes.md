# Failure Modes — Full Index

Every failure mode promoted to this skill, each carrying its full causal chain, incident, and correction. The highest-frequency modes also appear in full in SKILL.md.

---

**Failure: All-negative guard is vacuous when value is silently absent** — an optional chain or drifted parser returns `undefined` without error; every negative assertion (`expect(x).not.toBeDefined()`) passes trivially; the guard detects nothing. In the AC coverage audit, `view.acCoverage?.[k] ?? []` masked a renamed API field and all negative assertions passed, proving nothing about the fixture. Establish a positive control first: prove the harness can observe the value present, then assert absence.

**Failure: Source-text assertion gameable by comment** — `expect(src).toContain(rule)` is satisfied by a comment or string literal in the source; the behavioural constraint is unverified. A parity guard using this pattern was satisfied by a comment and shipped a broken constraint that passed review. Assert behaviour via execution; add a fail-safe default so the constraint is enforced even if the source text drifts; then complete a red→green cycle on the live path.

**Failure: Oracle blinded by widened accept-all set** — a whitelist-based losslessness/totality oracle widens its allowlist to accept every value; `Has()` always returns true; the oracle is vacuous while tests remain green. A whitelist was widened to pass a suite run, making the acceptance check vacuous. Inspect the oracle's data source, not just the test diff, and demand a red→green bite proof on the real handler.

**Failure: Guard detects but result discarded before output** — a correct detection whose result is swallowed before printing produces a guard that is always silent on failure; asserting the printed line and exit code is the only way to catch this. A lint pass iterating index nodes computed a violation count but discarded it before the exit-code path; tests stayed green through the regression. Assert the printed line and exit code, not the internal predicate; demand an end-to-end repro.

**Failure: Red→green proves sensitivity, not seam coverage** — stashing the fix and re-running proves the test bites but not that it runs both surfaces of the seam it was meant to cover. A stash-based bite proof confirmed a test failed when the fix was absent but the test was documented "Offline — stub store" and never ran the real wiring path. Read the test to confirm it exercises both surfaces; a stash-based proof is necessary but not sufficient.

**Failure: Freshness check proves consistency, not correctness** — comparing generated output against a fresh re-run of the same generator agrees even when both are wrong, because the generator's bug is stable. A freshness check confirmed two generated artifacts matched but neither was correct; the content contract was never pinned against an independent source. Pin the contract against a known-correct reference, not a re-run of the same generator.

**Failure: Fixture under gitignored path ships empty** — a fixture directory matching an unanchored ignore pattern is excluded from the installed package; tests run against an empty directory and pass vacuously. A fixture dir matched a broad unanchored pattern and was silently absent in CI; five agents confirmed "pre-existing" before one ran `git add -An`. Assert `git add -An <dir>` reports the expected file count; add `git check-ignore -v <dir>` to any fixture-registration step.

**Failure: Ambient env makes spec tests vacuous** — spec tests inheriting `CLAUDE_PROJECT_DIR` assert against the live repo tree; negative assertions always pass and prove nothing about the fixture under test. Spec parity tests inherited the ambient project dir and returned false "passing" results in every session they ran. Scrub `CLAUDE_PROJECT_DIR` and `CLAUDE_PLUGIN_ROOT` from the gate suite environment; use `env -u CLAUDE_PROJECT_DIR -u CLAUDE_PLUGIN_ROOT` before any spec-test invocation.

**Failure: Guard weakened to go green by subagent** — a subagent softens a security assertion and relabels the failing check as "stale," so the guard can never fail again after the change. A subagent modified a security guard and re-labelled the failing assertion as outdated to unblock a suite run. Diff test files between the red run and the green run; if the test changed, the green is not a valid proof.

**Failure: AC verified against wrong source yields wrong-but-green fix** — checking a criterion against the wrong module (not the one that enforces the criterion) produces a mis-transcribed AC that accepts incorrect implementations. An advisor checked an AC against a helper that delegated to the real enforcer; the check passed but the enforcer was broken. Trace the full enforcement path before accepting a criterion as satisfied; find the tolerant consumer, not just the first module that mentions the criterion.

**Failure: Mutation report with numbering gap hides the survivor** — a gap in a mutation report's numbering omits the surviving mutant, making the suite appear complete when it has a blind spot. A report listed mutants 1–4 and 6–9, omitting 5; the omitted mutant survived. Require exhaustive reports; treat any numbering gap as a red flag; verify the reported count equals the total mutation count before accepting coverage.

**Failure: Pipe to tail hides exit code** — piping a command through `tail` or another filter causes the shell to report the filter's exit code, not the original command's; a failing command appears to succeed. `tsc | tail -n 20 && echo $?` reported tail's status of 0 while tsc was red, hiding a type error for two sessions. Capture exit codes before any pipe: `tsc; echo "tsc exit: $?"` or use `set -o pipefail`.

**Failure: Tests bypass deployed invocation path** — tests invoke a hook or script directly (e.g., `node <path>`) rather than through the registered entry point; a regression in the deployed invocation path stays green. A hook tested via `node <path>` was 25/25 green while the bare-path registration exited 126 due to a missing exec bit. Assert the exec bit and spawn by the registered path in at least one test. Agents exercise the invocation variant easiest to script, which is systematically not the one humans use; a commit hook was proven "by a real `git commit`" via `-m` across a whole session while rejecting every editor, `--amend`, and `rebase -i` reword commit. Enumerate an interface's invocation variants in the criterion and require the one with the largest human population.

**Failure: Red→green perturbation destroys sibling work** — briefing a slice to perturb a tracked file for a bite proof silently reverts another slice's uncommitted fix; the perturbed file matches HEAD after revert and the sibling work is unrecoverable. A perturbation step stashed-then-restored a file that contained another slice's changes; `T4 ✓` still read complete. Use a scratch copy outside the repository (`cp <file> /tmp/backup`), never a stash or in-repo restore; verify byte-identity (`cmp`) before reporting proof.

**Failure: Git-stash baseline blind to untracked files** — bare `git stash` does not stash untracked files; a "confirmed pre-existing" baseline is false whenever new files are the cause of the failure. Five agents in one session each confirmed a failure was pre-existing after stashing, while the new untracked files causing it remained. Use `git stash -u` to include untracked files, or check `git status` for untracked files before accepting a baseline claim.

**Failure: Parity test blinded by narrowed input** — a parity test passes because the input was changed so both sides agree, rather than because the implementation is correct; every assertion stays intact but the test proves nothing. A parity guard was fixed by narrowing the input corpus so the two sides agreed coincidentally; the underlying divergence was never corrected. Diff inputs between test versions, not just assertions; document why rows agree (coincidental agreement is acceptable only when disclosed in source).

**Failure: Auditor shares the defect class** — an auditor checking for a pattern uses the same defective method the code under audit uses; absence claims are vacuous. A lowercase-only grep "proved" `@verifies` had zero adoption while the matcher was case-broken, and the audit itself used the same case-broken check. Include a known-present positive control in every absence claim; if the control is not found, the search method is broken.

**Failure: Guard blind to its own failure case** — a guard iterating parsed nodes can never detect a file that failed to parse into a node; the unparseable file is invisible to the check. A lint pass produced a clean report while the file causing the issue failed to parse and was never examined. Demand an end-to-end repro with the actual unparseable file; prefer a count-parity invariant (files-in equals files-examined) over cause-specific detection.

**Failure: Check discards its scope argument** — a check that accepts a positional file or path argument and silently ignores it, always scoping to a fixed subject (e.g. the working diff), reports clean when given a known-violating file. `gw comment-density report` accepted positional file arguments and discarded them, always scoping to the working diff; scanning a known-violating file reported clean. Verify the check's actual scope by inspecting its configuration or source, not its documentation; test it by passing a known-violating path and confirming the report changes.

**Failure: Fixture omits what production guarantees** — a check that only manifests inside a real environment (a git repository, a live service, a real filesystem) stays green in every test that runs in a bare temp directory. `bin/ledger init` wrote a required field only inside a git repository; every test ran in a bare `mkdtemp` dir; a CLI that could not initialise in any real repository stayed green indefinitely. Replicate the production environment constraint in the fixture, or assert that the test environment matches the constraint the code under test requires.

**Failure: Assertion indistinguishable on success from early return** — an assertion on a value both the working and broken implementations produce proves nothing; exit code 0 is produced identically by a successful `exec` and a premature `exit 0`. The live instance is `test/hooks/hook-invocation-path.test.ts` against the `hooks/session-start` shim. Assert a value that only the intended code path can produce: a distinctive exit code, a specific output string, or a side-effect observation.

**Failure: Derived iteration is not a derived assertion** — a guard that imports the source of truth, iterates it, and is named after it can still be vacuous if each assertion is satisfiable by incidental text; the derivation makes it look airtight while it verifies nothing. An `AC-11 gitmessage drift check` looped `for (const type of COMMIT_TYPES) expect(content).toContain(type)`; `'fix'` was satisfied by the word "prefix" elsewhere in the file, so deleting the entire type list under test left the guard green. Anchor each match on the delimited form as it actually appears — the joined line (`COMMIT_TYPES.join(' | ')`) or a delimited token (`` `${type}` ``) — and prove it by deleting the list under test and by adding a member.

**Failure: File-list source silently narrows scope** — a checker enumerating its subjects from `git ls-files` (or any index-backed listing) cannot see an untracked file; a newly authored violating file passes every run until the moment it is committed, and the author's green is truthful. `scripts/check-comments.mjs:55` enumerates via `git ls-files`; a newly written ceiling test passed `pnpm run check` while untracked and turned the check red on the commit that added it. Read the enumeration source, not the documented scope; prove the check by creating a known-violating file, leaving it untracked, and confirming the result changes.

**Failure: Comparison reads a projection, not the payload** — a verification comparing a record's identifier and headline field passes while sibling fields are silently lost. A restoration of journal decision `D-31` was confirmed by comparing `id` and `decision` text only; the restore had dropped a two-entry `alternatives` array and flipped `status` from `proposed` to `accepted`, and neither was visible to that comparison. Diff whole payloads field by field against the source-of-truth record, and state in the report which fields were compared.

**Failure: Assertion cancels its input algebraically** — substituting the production formula into the assertion shows the input does not survive. A cost-per-token assertion appeared to measure 30 real transcripts, but `cost.cache_read / tokens` reduces to `PRICE_PER_MTOK / M`; the token count cancels and the expression is a ratio of two constants, identical for a real session, a synthetic fixture, or an empty file. Tell-tale: the same production constant appears on both sides of the division. Substitute symbolically before accepting, then perturb production and expect red.

**Failure: Fixture sits off the boundary it tests** — fixtures far from a threshold return the same verdict for every plausible threshold and constrain nothing. Prose-guard parity fixtures scored Jaccard `0.00` against a `0.4` threshold, so they passed for any threshold in `(0,1]` and proved only that two strings were unrelated. Bracket the boundary: at least one fixture strictly below and one strictly above, each close enough that a plausible move of the threshold flips it.

**Failure: Slack in a ratchet permits the growth it detects** — a ceiling set above the current measured value licenses exactly the regression it exists to catch. A skills-surface ratchet was set to `2154` against a current `1810` — 19% headroom — by importing a `1.19` factor from a sibling test where that number was a units-conversion ratio between two measurement methods, not an allowance. Set the ceiling equal to the current measured value, and record in the docblock what any adjacent factor means so the next reader cannot re-import it as slack.

**Failure: Comparator admits the defect's value** — a non-strict comparator survives the mutant producing exactly its boundary. `expect(turn_count).toBeLessThanOrEqual(record_count)` survived the mutant `turn_count = record_count` in the one test carrying the requirement's `@verifies` annotation; turns are strictly fewer than records in any real session. Choose the strict form whenever the real invariant is strict, and confirm by writing the boundary value as a mutant.

**Failure: Test body never ran but reports passed** — a bare `return` inside a Vitest `it()` reports the test as **passed**, not skipped; a guarded early return for a missing fixture directory emits a green tick indistinguishable from a real pass, and did so while the defect it guarded was live. Use `ctx.skip()` or `it.skipIf`, then prove it by running with the precondition absent and confirming the runner prints *skipped*.

**Failure: Two binaries share a command name, only one can see the data** — when two implementations answer the same command, an empty read is ambiguous between "the store is empty" and "this implementation reads a different store". `bin/journal compile <motive> --stdout --json` reads the JSONL shards and returns a populated decision log; `gw journal compile` (`src/gw/cli/commands/journal.ts:66-70`) reads `<tracker>/motives/<motive>/decisions/*.md`, a directory no motive in this repo has, and returns `[]`. An agent that ran the second concluded the decision store was empty and generalised that into advice, which would have suppressed a future real check. Before reporting an empty read as evidence of absence, confirm which implementation ran and that it returns non-empty on known-present data.
