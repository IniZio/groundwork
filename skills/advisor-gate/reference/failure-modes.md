# Advisor Gate — Failure Modes

Each entry: failure name → causal chain → correction. Source incidents live in the memory store; slugs are listed for cross-reference.

---

**Failure: advisor approves on fabricated evidence** — the advisor completion gate returns APPROVE citing a line, test, or file that does not exist → the orchestrator records the gate on false evidence → the regression ships and is discovered only after the session ends. Verify each load-bearing claim in the verdict (cited file path, line number, test name, exit code) against source before calling `gw ledger gate`. One repo-wide grep or a direct Read of the cited file costs one tool call and catches the fabrication. Memory: `advisor-false-approve`.

**Failure: gate recorded without orchestrator write token** — a general-purpose subagent writes `gate.advisor=APPROVE` directly without the ledger write token → the stop-gate sees a gate entry but cannot verify its provenance → the session ends on a bypassed gate, and the completing subagent's claim is unverifiable. The write token is orchestrator-only; the orchestrator records the gate itself after receiving the verdict. Never relay a gate write to a subagent. Memory: `stopgate-token-bypass`.

**Failure: gate run in detached worktree** — a gate agent creates a detached worktree at HEAD to run attribution comparisons → the worktree lacks `.groundwork/` runtime state and the node_modules layout that several CLI and spec-lint tests depend on → phantom suite failures emerge, contradicting a prior green run in the primary directory → an unnecessary diagnose cycle begins and a valid prior APPROVE is almost retracted. Detached worktrees produce harness artifacts that look like regressions. Brief gate agents not to create worktrees. When a verdict contradicts a prior green run, re-run in the primary working directory yourself before acting. Memory: `advisor-worktree-phantom-failures`.

**Failure: filtered run hides cross-file breakage** — a slice's filtered test run ("41 passed") reports green while the full suite has failures in cross-file enforcement modules → the gate is submitted on a partial view → session-end unfiltered run fails. Shared-enforcement changes (hooks, guards, spec schemas) require an unfiltered run in addition to any per-slice run. The gate invocation command already specifies unfiltered; reject evidence from a named-file filter. Memory: `filtered-run-hides-cross-file-breakage`.

**Failure: per-slice green, suite red** — each slice's own test file passes in isolation, yet the full suite has cross-file failures (observed: 9 failures in a motive with 5 passing slices) → the session-end gate is submitted on slice-level evidence → suite fails at gate time, requiring re-triage. Always run the full unfiltered suite and a HEAD baseline before the completion gate, not just the files the slice touched. Memory: `per-slice-green-suite-red`.

**Failure: implementer self-report overstates evidence** — an implementer reports "28 tests pass, 3 new tests added" when the real numbers are different, or reports a passing test for a behaviour the test does not exercise → orchestrator records the gate on inflated numbers → regressions go undetected until a later session. Self-reported counts and test coverage claims require direct verification: run the suite yourself or read the test file to confirm it exercises the claimed behaviour. Memory: `implementer-self-report-reliability`.

**Failure: pre-existing failure claims need diff proof** — stable failure count across waves is accepted as "pre-existing baseline" → a session-introduced regression is laundered as inherited debt → the actual regression ships. A failure that predates this wave can still postdate this session/branch. Before accepting any pre-existing claim, diff the failing artifact against committed HEAD and check whether the failing identifiers appear as added lines. Memory: `pre-existing-failure-claims-need-diff-proof`.

**Failure: three unrelated suite failure modes misattributed** — the vitest suite has three distinct failure mechanisms (onTaskUpdate RPC timeout flake showing zero FAIL lines; spawn starvation showing empty-stdout DENY; ambient-env leakage from CLAUDE_PROJECT_DIR/CLAUDE_PLUGIN_ROOT showing ~92 phantom failures) → attributing a failure without naming the mechanism produces a wrong diagnosis → a correct run appears broken, or a broken run appears correct. Name the mechanism before attributing: check for FAIL lines (flake), check for DENY output (starvation), check env var leakage (scrub CLAUDE_PROJECT_DIR and CLAUDE_PLUGIN_ROOT). Memory: `two-distinct-suite-failure-modes`.

**Failure: review attributes diff-introduced regressions to pre-existing work** — a reviewer diffs HEAD-vs-working-tree and blames the slice for the operator's uncommitted changes that predate the slice → a REJECT verdict is wrong; the slice is clean → the operator's work is overlooked. Attribute failures: diff the files changed by this session's slice, not the whole tree, and check whether the failing identifiers appear in that diff. Memory: `review-must-attribute-diff-vs-pre-existing`.

**Failure: visual evidence stale on regeneration** — a qa PASS and screenshots are captured before a data-regeneration step that changes the rendered output → the gate is submitted citing screenshots of the pre-fix render → the post-fix render is never verified. Treat visual/qa evidence as invalidated by any downstream data or build change. After regenerating data or rebuilding, re-capture and re-read screenshots before the gate. Memory: `visual-evidence-stale-on-regen`.

**Failure: enumerated search surfaces inherit blind spots** — a verification brief lists directories to search (src/, hooks/, test/…) and omits one (pi/) → verifier agents treat the enumeration as the complete surface → multiple independent agents both return "zero references, CONFIRMED DEAD" for a symbol that pi/ imports → absence claim is correlated, not independent. Phrase verification as "search the whole repo; pay particular attention to X, Y, Z" and require the verifier to report the surfaces it discovered. Demand a positive control (a known-present reference the search finds) before accepting any absence claim. Memory: `enumerated-search-surfaces-inherit-blind-spots`.

**Failure: calling a spec sentence false without tracing the full enforcement path** — enforcement of a spec criterion splits across classifier, CLI, and hook; an advisor checking only one module concludes "not needed" and calls the spec line false → a correct spec is retracted → the enforcement gap ships as intended behaviour. Trace the full enforcement path (all three layers) before concluding a criterion is unmet or a spec sentence is wrong. Mirror case: "GRAPH_MUTATE absent from motive-compile but natively handled in motive-graph-fold." Memory: `trace-whole-enforcement-path-before-calling-spec-false`.
